## Optimization Points
- The "Environment Prerequisites (probe at generation time)" rule proved to be the highest-value instruction in this command, but it is scoped to "external environment (docker daemon, network-pullable images, a live cluster, special hardware)". That framing does not obviously cover "the build system the plan selected is not installed", which is exactly what happened here (meson and ninja both absent). Broadening the examples to include the toolchain the plan itself depends on would make the probe's intent unmistakable — without it an agent could reasonably skip probing and emit 47 tasks that mostly cannot run.
- Probing surfaced that the project does not build at all as shipped (automake -Werror escalates a GNU-pattern-rule warning; then four AM_CONDITIONALs defined inside conditionally-invoked macros break configure). Nothing in the command anticipates discovering that the BASELINE is broken, yet a baseline-relative success criterion is unverifiable in that state. Worth adding: when a task depends on measuring the current system, verify the current system actually runs before emitting tasks that compare against it.
- Probing also inverted a load-bearing premise carried from requirements through plan: the spec claimed bundled deps "are fully rebuilt every time", but the LuaJIT rule has no prerequisites, so it is never rebuilt once present (stale artifact, an under-build correctness bug). The command's step 2 says to load design documents as inputs, with no instruction to validate their factual claims against the tree. A short "verify the premises the tasks will be built on" step would have caught this two commands earlier; as it stands the error propagated through requirements.md and plan.md unchallenged.
- The DoD/GATE format rules (- DoD-N: / - GATE-N: rather than checkboxes) are well specified and easy to comply with, and the validation regex given in step 5 is directly runnable. No change needed there; noting it as the counter-example of a rule that works.
