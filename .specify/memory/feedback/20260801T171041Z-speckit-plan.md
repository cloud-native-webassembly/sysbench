## Optimization Points
- The command's Outline step 1 unconditionally runs create-new-plan.sh, which copies the template over plan.md. This run was interrupted after plan.md had been filled; re-running setup on resume would have destroyed the filled plan and all its Phase 1 cross-references. The command needs an explicit resume clause: if plan.md already exists and contains no residual placeholders, skip the setup script and continue from the first missing Phase 1 artifact. As written, a resumed run silently reverts completed work.
- The "execution-verify emitted command examples" gate in the Post-Generation Quality Gate assumes the target tool is installed. Meson was absent from this environment, so the meson invocations could not be verified. The gate offers option (b) "pinned by a contract test", which I used (contract C-16), but it gives no guidance on how to MARK unverified examples in the emitted artifacts. I adopted an explicit per-example legend, which seems worth making the standard: silently shipping unverified examples alongside verified ones is exactly the drift the gate exists to prevent, and the reader cannot tell them apart without a marker.
- Phase 1's contract guidance is REST/GraphQL-shaped ("For each user action → endpoint", "Output OpenAPI/GraphQL schema"). For a build-system, CLI, or library feature there is no endpoint surface, and following the instruction literally would produce fabricated artifacts. The useful generalization is "specify the feature's externally-depended-upon interface" — here that was build options, commands, exit codes, and diagnostics. Worth stating so agents document the real contract surface instead of either inventing endpoints or skipping contracts/ entirely.
- Deriving the Constitution Check table dynamically caught nothing wrong this run (8 principles, correct order), but the verification was only possible because I diffed the rendered rows against the constitution headings with paste. Recommending that diff as an explicit step would make the anti-drift intent of the existing instruction actually checkable rather than aspirational.
