# Feature Detail: Wasmtime Runtime Backend

**Feature ID**: 006  
**Name**: Wasmtime Runtime Backend  
**Description**: Integrate the Wasmtime SDK as a sysbench WASM backend; currently a registered stub with no engine calls.  
**Status**: Draft  
**Created**: 2026-08-01  
**Last Updated**: 2026-08-01

## Overview

Wasmtime is the Bytecode Alliance reference runtime and the fourth engine this fork targets.
As with Wasmer, the scaffolding exists — configure detection, conditional build wiring, a
runtime descriptor, a factory function — but no Wasmtime API call has been written, and the
Wasmtime C API header is not even included. This is the least advanced of the four backends.

Completing it closes the "mainstream runtime" set that motivates the whole WASM effort, and
gives the comparison story a widely-recognised baseline engine.

## Latest Review

Reviewed 2026-08-01 by code inspection during registry bootstrap. `src/sb_wasmtime.c` is 53
lines. All three implemented functions have empty bodies: `sb_wasmtime_init`,
`sb_wasmtime_destroy`, `sb_wasmtime_load_module` (`src/sb_wasmtime.c:38-40`). No
`wasmtime.h` / `wasm.h` include is present, so the file references no engine type at all.
Verdict: **stub**.

## Key Changes

1. Add the Wasmtime C API include and implement `sb_wasmtime_init` to create the engine
   (`wasm_engine_new` / `wasmtime_config_*`), replacing the empty body at
   `src/sb_wasmtime.c:38`.
2. Implement `sb_wasmtime_create_sandbox` — currently absent entirely — to create a store,
   compile the module (`wasmtime_module_new`), and instantiate it
   (`wasmtime_instance_new`) per sysbench thread, and assign it to the descriptor at
   `src/sb_wasmtime.c:42-47`.
3. Implement `function_apply` / `function_available` via `wasmtime_instance_export_get` and
   `wasmtime_func_call`, marshalling the single `i64` carrier per the Feature 002 contract.
4. Implement `addr_app_to_native` / `addr_native_to_app` over `wasmtime_memory_data` so
   buffer-passing workloads (Feature 007) work on this backend.
5. Implement `sb_wasmtime_destroy` with real teardown of instance, store, module, engine.
6. Fix the return-type mismatch: `sb_wasmtime_load_module` is declared to return
   `sb_wasm_module` by value (`src/sb_wasmtime.c:40`) while the vtable member
   `sb_wasm_load_module_func` expects `sb_wasm_module *` (`src/sb_wasm.h:79`).
7. Fix `m4/sb_wasm.m4:202`, which calls `AC_SUBST([WAMR_HOME])` inside the Wasmtime block
   instead of `AC_SUBST([WASMTIME_HOME])`, so `WASMTIME_HOME` never reaches the Makefiles.
8. Implement or delete the five functions declared in `src/sb_wasmtime.h:26-34`
   (`sb_wasmtime_done`, `sb_wasmtime_custom_command_defined`,
   `sb_wasmtime_report_thread_init`, `sb_wasmtime_report_thread_done`, `sb_wasmtime_loaded`)
   that have no definitions.

## Implementation Notes

- Configure support already exists: `AX_CHECK_WASMTIME` (`m4/sb_wasm.m4:171-176`) provides
  `--with-wasmtime`, discovers the SDK from `${WASMTIME_HOME}` or the `wasmtime` binary on
  `PATH`, and emits `-lwasmtime` plus `-lpthread -ldl -lm` (`m4/sb_wasm.m4:200`) — extra
  link flags the other three backends do not request. Build wiring exists at
  `src/Makefile.am:81`.
- Dispatch support already exists: `src/sb_wasm.c:108-112` maps `SB_WASM_RUNTIME_WASMTIME` to
  `create_wasmtime_runtime()` under `#ifdef HAVE_WASMTIME`.
- Blocking hazard: with `create_sandbox` unset, `sb_wasm_op_thread_init` dereferences a NULL
  function pointer at `src/sb_wasm.c:231`. A guard in Feature 001/002 should land first.
- No `scripts/wasmtime/` directory and no `WASMTIME_OPTS` in `scripts/env.rc` exist, unlike
  WAMR and WasmEdge — this harness asymmetry must be closed as part of this feature.
- Wasmtime is JIT-first (Cranelift) with an optional AOT `.cwasm` path. Since compilation
  cost lands differently than in an interpreter, the chosen mode must be explicit and
  reported or the numbers will not be comparable to WAMR's interpreter results.

## Future Evolution Suggestions

- Support Wasmtime's AOT (`wasmtime compile` / `wasmtime_module_deserialize`) path as a
  distinct measured configuration.
- Add `scripts/wasmtime/run.sh` and `scripts/wasmtime/debug.sh` mirroring the WAMR scripts.
- Consider separating first-call (compile+instantiate) latency from steady-state call
  latency in reporting, since JIT engines warm up.
