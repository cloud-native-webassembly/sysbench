# Feature Detail: Runtime Debug Harness Scripts

**Feature ID**: 011  
**Name**: Runtime Debug Harness Scripts  
**Description**: Per-runtime shell wrappers and shared environment file for running and debugging WASM benchmarks (DFM).  
**Status**: Implemented  
**Created**: 2026-08-01  
**Last Updated**: 2026-08-01

## Overview

Invoking a WASM benchmark requires a long command line: the sysbench binary, verbosity and
report-interval flags, `--type=wasm`, the runtime selector, the module path, and the `run`
subcommand. This feature captures those invocations as per-runtime `run.sh` / `debug.sh`
wrappers over a shared `env.rc`, so a developer or agent can reproduce a run without
reconstructing the flags — the repeatable-execution surface that Constitution Principle VIII
(Better-Harness Orientation) cares about.

## Latest Review

Reviewed 2026-08-01 by code inspection during registry bootstrap. Wrappers exist for the two
working backends only, and the coverage is asymmetric with the stated four-runtime goal:
`scripts/wamr/` and `scripts/wasmedge/` each contain `run.sh` and `debug.sh`, while
`scripts/wasmer/` and `scripts/wasmtime/` are absent, and `env.rc` defines `WAMR_OPTS` and
`WASMEDGE_OPTS` but no `WASMER_OPTS` / `WASMTIME_OPTS`. The two `debug.sh` scripts also
disagree on the module path, so one of them targets a file that is never produced.

## Key Changes

1. Added `scripts/env.rc` exporting the shared harness variables: `SYSBENCH_PRINT_OPTS`
   (`--report-interval=1 --verbosity=5`), `SYSBENCH` (binary plus
   `--thread-init-timeout=0`), `WAMR_OPTS`, and `WASMEDGE_OPTS`.
2. Added `scripts/wamr/run.sh` and `scripts/wasmedge/run.sh` invoking
   `${SYSBENCH} ${<RT>_OPTS} "$@" src/wasm/wasm run`.
3. Added `scripts/wamr/debug.sh` and `scripts/wasmedge/debug.sh` wrapping the same
   invocation in `gdb -args`.
4. Added `scripts/build.sh` as the canonical build entry point (`autogen.sh`, `configure`,
   `make clean`, `make -j32`).
5. Set toolchain paths in `env.rc` from `LLVM_HOME`, `GCC_HOME`, and `WABT_HOME`, and pinned
   `LANG=C` for stable log parsing.

## Implementation Notes

- `scripts/wasmedge/debug.sh` references `src/wasm/sb_wasm_test.wasm` while
  `scripts/wamr/debug.sh` references `src/wasm/wasm`. Neither name matches any of the seven
  artefacts produced by `src/wasm/Makefile.am` (Feature 008), so both paths are stale.
- `env.rc` consumes `LLVM_HOME`, `GCC_HOME`, and `WABT_HOME` without defining or checking
  them. If unset, `LD_LIBRARY_PATH` degrades to `/lib64:/lib64` and `/bin` is prepended to
  `PATH` — silently wrong rather than a clear error. No absolute paths are hardcoded, so the
  file is portable in principle.
- `scripts/build.sh` omits `--with-wasm`, which per Feature 009 means it currently builds a
  sysbench with no WASM support at all. This is the highest-impact defect in the harness.
- The scripts assume they are run from the repository root (relative `src/sysbench` and
  `src/wasm/...` paths) but do not enforce it.
- `--thread-init-timeout=0` disables a safety timeout; useful when a debugger is attached,
  but it should not be the default for measurement runs.
- Status was derived from source inspection during registry bootstrap, not from a completed
  `/speckit.plan` → `/speckit.implement` cycle.

## Future Evolution Suggestions

- Add `scripts/wasmer/` and `scripts/wasmtime/` wrappers plus the matching `*_OPTS` in
  `env.rc` once Features 005 and 006 land, restoring symmetry across all four runtimes.
- Point the `debug.sh` scripts at a module that the build actually produces, and fail loudly
  if the path is missing.
- Validate `LLVM_HOME` / `GCC_HOME` / `WABT_HOME` in `env.rc` and error out when unset.
- Add a single sweep script that runs one workload across every built runtime, feeding
  Feature 013.
