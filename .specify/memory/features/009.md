# Feature Detail: WASM Build Configuration

**Feature ID**: 009  
**Name**: WASM Build Configuration  
**Description**: Autoconf/automake wiring that detects each WASM SDK and conditionally compiles the corresponding backend.  
**Status**: Implemented  
**Created**: 2026-08-01  
**Last Updated**: 2026-08-01

## Overview

Four optional SDKs, each of which may be absent on any given machine, must not break the
build. This feature is the configure-time machinery that makes each runtime backend
independently optional: a master `--with-wasm` gate, four per-runtime `--with-<runtime>`
flags, SDK discovery, and `AM_CONDITIONAL` blocks that add the matching `sb_wasm*.c` sources
and link flags only when the SDK was found.

It is what upholds the constitution's requirement that "a build can omit a runtime whose SDK
is unavailable without breaking the tree", and it is the reason `src/sb_wasm.c`'s dispatch
switch can be `#ifdef`-guarded per engine.

## Latest Review

Reviewed 2026-08-01 by code inspection during registry bootstrap. The structure is sound and
symmetric across all four runtimes, but four defects undermine it — one of which means the
project's own build script produces a binary with no WASM support at all:

1. `scripts/build.sh:2` passes `--with-wamr --with-wasmedge` but **not** `--with-wasm`.
   Because `SB_WASM` (`m4/sb_wasm.m4:227-234`) only invokes the four `AX_CHECK_*` macros when
   `--with-wasm` was given, the per-runtime flags are silently ignored and `HAVE_WASM` is
   false.
2. `m4/sb_wasm.m4:202` calls `AC_SUBST([WAMR_HOME])` inside the Wasmtime block instead of
   `AC_SUBST([WASMTIME_HOME])`.
3. All four per-runtime help strings claim "(default is enabled)" while the
   action-if-not-given branch sets `ac_cv_enable_<rt>=no` — the real default is disabled.
4. A missing SDK triggers `AC_MSG_ERROR` ("Unable to find <runtime> runtime"), so requesting
   a runtime whose SDK is absent aborts configure rather than degrading gracefully.

## Key Changes

1. Added `m4/sb_wasm.m4` defining `SB_WASM` (line 219) plus `AX_CHECK_WAMR` (line 22),
   `AX_CHECK_WASMEDGE` (line 71), `AX_CHECK_WASMER` (line 121), `AX_CHECK_WASMTIME`
   (line 170).
2. Invoked `SB_WASM` from `configure.ac:156` and appended all four `*_CFLAGS` to
   `AM_CPPFLAGS` at `configure.ac:380`.
3. Established the SDK discovery convention: honour `${<RT>_HOME}` if set, else locate the
   runtime binary (`iwasm` / `wasmedge` / `wasmer` / `wasmtime`) on `PATH` and derive the
   home via `readlink -f $(dirname $(dirname $(which ...)))`.
4. Derived flags by convention per runtime: `-I${HOME}/include`, `-L${HOME}/lib
   -Wl,-rpath=${HOME}/lib`, and `-l<runtime>`; Wasmtime additionally requests
   `-lpthread -ldl -lm` (`m4/sb_wasm.m4:200`).
5. Added conditional source and link wiring in `src/Makefile.am:59-85`: `HAVE_WASM` adds
   `sb_wasm.c/.h`; each `HAVE_<RT>` adds its `sb_<rt>.c/.h` plus `$(<RT>_LIBS)` and
   `$(<RT>_LDFLAGS)`.
6. Added `src/wasm/Makefile` to `AC_CONFIG_FILES` (`configure.ac:417`) and a configure
   summary block reporting each runtime's discovered home and flags
   (`configure.ac:455-487`).

## Implementation Notes

- Discovery is binary-presence-based, not header/library-based: finding the `wasmtime` CLI on
  `PATH` is taken as proof that `wasmtime.h` and `libwasmtime` exist at conventional
  locations. That inference fails for SDK layouts that ship a CLI without dev files.
- No `pkg-config` is used and no SDK version is checked or pinned anywhere, so a build
  silently accepts whatever version happens to be installed — a comparability hazard for
  benchmark results (see Feature 016).
- `-Wl,-rpath` bakes the SDK library path into the binary, which aids local runs but makes
  the artefact non-relocatable.
- Nothing in `third_party/` vendors a WASM SDK; only `cram`, `luajit`, and
  `concurrency_kit` are vendored. All four WASM SDKs are external prerequisites.
- Status was derived from source inspection during registry bootstrap, not from a completed
  `/speckit.plan` → `/speckit.implement` cycle.

## Future Evolution Suggestions

- Add `--with-wasm` to `scripts/build.sh`, or make a per-runtime flag imply the master gate,
  so the documented build path actually enables WASM.
- Replace `AC_MSG_ERROR` on a missing SDK with a warning that disables just that runtime,
  matching the "omit a runtime without breaking the tree" intent.
- Verify SDKs by compiling a probe against the header and linking the library rather than by
  locating the CLI binary.
- Correct the misleading help strings and pin minimum SDK versions.
