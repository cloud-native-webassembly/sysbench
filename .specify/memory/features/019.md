# Feature Detail: Modern Build System

**Feature ID**: 019  
**Name**: Modern Build System  
**Description**: Replace GNU Autotools with a modern build system delivering incremental parallel builds and readable, maintainable configuration.  
**Status**: Planned  
**Created**: 2026-08-01  
**Last Updated**: 2026-08-01

## Overview

The project builds through GNU Autotools totalling **5,003 lines**, of which ~3,072 are
vendored third-party `m4` macros the project neither wrote nor maintains. That footprint
carries two concrete costs: builds cannot reuse prior work (bundled LuaJIT and Concurrency Kit
are cleaned and re-copied on every invocation because neither supports VPATH), and answering
"how is this dependency found?" requires reading vendored macro code.

This feature covers the full migration to a modern build system and the **complete retirement**
of Autotools. It is whole-project scope — database drivers, scripting backends, bundled
dependencies, WASM runtimes, packaging, and CI — which is why it exists as its own Feature
rather than binding to the WASM-scoped Features 009 or 016.

## Latest Review

Planned 2026-08-01 by `/speckit.plan`. Status advanced `Draft` → `Planned`; artefacts at
`.specify/specs/001-modernize-build-system/` (`plan.md`, `research.md`, `data-model.md`,
`quickstart.md`, `feature-ref.md`, `contracts/` ×3). Constitution Check: 7 of 8 principles Pass;
Principle VI (Measurement Integrity) is ⚠ Partial by design and tracked in Complexity Tracking,
because SC-001–SC-004 are ratios against a baseline that must be captured before migration work
begins.

**Build system selected: Meson ≥1.3 + Ninja.** The decisive factor is bundled-dependency
incrementality — the project's actual pain. Meson's dependency wrappers rebuild only on real
source change; CMake's `ExternalProject_Add` offers only `BUILD_ALWAYS ON` (reproduces the
current always-rebuild bug) or `OFF` (stale artefacts). Distro packaging, expected to be the
deciding factor, was found **non-discriminating**: Debian (`meson.pm`), Fedora (`%meson*`), and
snapcraft all support both candidates natively. CMake is recorded as the documented fallback.

**Three findings that changed the design:**

1. **Baseline corrected.** Direct re-measurement gives 5,074 total / **1,905 project-authored** /
   3,169 vendored, versus the spec's earlier 5,003 / 1,334 / 3,072. `requirements.md` was updated
   per Constitution Principle II; SC-004's target is now ≤762 lines.
2. **WASM guest modules are not built today.** `src/wasm/Makefile.am:41-45` uses space
   indentation where Make requires tabs, so those recipes are dead. "Porting existing behaviour"
   would have ported a no-op; the plan implements intended behaviour instead.
3. **Contract C-7 execution-verified during planning.** A candidate `embed-file.py` produced
   byte-identical output for all 6 embedded headers — after a first attempt failed on
   `src/python/sysbench.py`, which has no trailing newline and therefore places the closing `;`
   on the final literal's line. That rule is now normative, preventing a silent change to a
   generated header.

**Tasks generated 2026-08-02** (`tasks.md`, 47 tasks: 39 actionable + 8 pre-deferred). Status
remains `Planned` — `/speckit.tasks` does not advance status.

**Scope narrowed by user directive**: this round delivers the **build-system framework only**.
Environment probing confirmed `meson`, `ninja`, all four WASM runtime SDKs, WASI-SDK, `valgrind`,
and `debuild`/`rpmbuild`/`snapcraft` are **absent** from the image, so the build environment must
be rebuilt first. All eight tasks requiring build/test/package *execution* are pre-marked `[~]`
with their blocker named inline. Autotools deletion (T047 / gate G-6) is explicitly out of scope.

**Three measured findings from task-generation probing (all supersede earlier assumptions):**

1. **The tree does not build as shipped.** `sh autogen.sh` fails because `configure.ac:31` passes
   `-Werror` to automake and `src/wasm/Makefile.am:41` emits a GNU-pattern-rule warning. After
   bypassing that, `./configure` fails with `conditional "HAVE_WAMR" was never defined` — the four
   per-runtime `AM_CONDITIONAL`s sit inside macros that `SB_WASM` invokes only under
   `--with-wasm`, but automake requires them unconditionally. The **default** configure path is
   broken.
2. **The incrementality premise was inverted.** The spec claimed bundled dependencies rebuild
   every time. Measured: `third_party/luajit/Makefile.am:25` declares its rule with **no
   prerequisites**, so touching `third_party/luajit/luajit/src/lj_api.c` produced **zero** compiles
   and left the archive mtime unchanged. The real defect is **silent staleness (under-build)** — a
   correctness bug, strictly worse than the slowness assumed.
3. **The build is not slow.** Measured medians (192-core x86_64, warm cache): full build **6 s**,
   no-op **55 ms**, single-file **178 ms** (1 compile). SC-001/SC-002 originally demanded <5.5 ms
   and <44 ms — unachievable and not build-system-bound. Both were **restated as non-regression
   criteria** by user decision. The migration's justification re-anchors on readability
   (1,905 → ≤762 lines) and correctness.

**Implemented 2026-08-02 (framework round)** — `/speckit.implement` closed 39 of 47 tasks; 8 remain
deliberately deferred. **Status stays `Planned`**: the substantive acceptance gates (G-2…G-5) are
unexecuted because the tooling is absent, so advancing to `Implemented` would overstate what was
verified.

**Delivered**: 10 Meson files (1,060 lines total / 693 code) replacing `configure.ac` + 18
`Makefile.am` + 21 `m4` macros; `scripts/embed-file.py` (byte-identical to the `sed` rules it
replaces, verified against all 6 inputs); `scripts/build-bundled.sh` (out-of-tree bundled builds —
executed for real, producing a 970 KB / 70-object LuaJIT archive while leaving the source tree
pristine); 4 contract tests under `tests/build/`; all 7 downstream consumers migrated.

**Test results**: `test_option_parity.py` PASS (22/22 capabilities = 15 project options + 6 Meson
built-ins + 1 recorded drop); `test_dependency_docs.py` PASS (8/8 SDKs documented, `WASI_SDK_HOME`
wired); `test_no_vendored_macros.py` PARTIAL; `test_consumer_refs.py` FAIL by design — it is the
gate G-6 acceptance check and now reports exactly 2 remaining references, both in files T047 deletes.

**SC-004 split result**: vendored-macro independence **passes** (0 of 13 vendored `m4` files needed;
all 3,169 lines deleted rather than ported), but the line budget **misses** — 1,060 total vs the 762
target. Code-only is 693 lines (36.4%), which would meet it. The 367 non-code lines are comments
citing `file:line` evidence for each defect fixed; trimming them to hit the number would remove the
justification for the migration. Recorded as a shortfall with three resolution options.

**Two artefact errors found and corrected during implementation**: (1) `contracts/option-mapping.md`
double-counted option 5 (`--enable-largefile`) as both a project option and a built-in, so its
"16 project / 5 builtin" tally was wrong — corrected to 15/6/1; (2) `.travis.yml` deleted by user
decision (last touched 2021-02-06, superseded by GitHub Actions in 2023).


## Key Changes

1. **Decided**: Meson ≥1.3 + Ninja, justified in `research.md` § Decision 1 against
   capability-parity (FR-002) and readability (FR-010) requirements. CMake documented as fallback.
2. Reproduce all 22 user-facing configuration capabilities and the 12-conditional matrix, so
   any valid subset of optional components still builds.
3. Deliver incremental, whole-project-parallel, out-of-tree builds; stop re-cleaning bundled
   dependencies that have not changed.
4. Keep both code-generation steps working: `sed`-based embedding of Lua/Python sources into C
   headers, and WASI-SDK cross-compilation of the 7 WASM guest modules.
5. Migrate all 7 downstream consumers plus README, then **delete** `configure.ac`, the 18
   `Makefile.am` files, `autogen.sh`, and the 21 `m4/` macros.
6. Narrow the supported platform set to Linux (x86_64 + aarch64) and macOS, dropping Sun
   Studio, PowerPC cache-line overrides, x86 CPUID probes, and FreeBSD-specific handling.
7. Fix three build-correctness defects carried from the current system (see Implementation
   Notes).

## Implementation Notes

- **Full retirement is the agreed end state** (user decision, 2026-08-01). Autotools files are
  removed only after every consumer is migrated and verified; the SC-004 target of ≤40% of the
  current 1,334 project-authored lines depends on this.
- **Replacement technology is deliberately unresolved** at requirements time. The plan must
  produce a capability-mapping table (one row per current option) before committing.
- **Baseline capture is a hard prerequisite.** Success criteria SC-001–SC-003 are ratios
  against Autotools timings that do not yet exist. Per Constitution Principle VI, "improved"
  may only be claimed from comparable before/after evidence, so timings must be recorded on
  the current tree before migration work lands.
- **Defects to fix, not carry forward**: the master-gate omission in `scripts/build.sh:2`
  (produces a binary with no WASM support); `AC_SUBST([WAMR_HOME])` in the Wasmtime branch at
  `m4/sb_wasm.m4:202`; and WASM guest modules declared as `bin_PROGRAMS` in
  `src/wasm/Makefile.am:24-31`, which would install them into `bindir`.
- **Platform narrowing is evidence-based**: CI only exercises ubuntu-20.04/22.04, and no WASM
  runtime SDK targets Sun Studio.
- **Overlap with existing features**: Feature 009 (WASM Build Configuration, Implemented) owns
  `m4/sb_wasm.m4` and will be superseded in its build-wiring aspects; Feature 016 (Pinned SDK
  Provisioning, Draft) overlaps Story 4 of the spec. Both must be reconciled when this feature
  reaches `Implemented`.

## Future Evolution Suggestions

- Once the new system is authoritative, add the configuration matrix from SC-006 to CI so the
  conditional matrix is continuously verified rather than checked once at migration.
- Revisit whether bundled LuaJIT and Concurrency Kit should remain in-tree, become submodules,
  or move to a package manager — deferred from this feature's scope.
- Consider recording build provenance (compiler, dependency versions) into the binary, feeding
  Feature 013's cross-runtime comparability requirements.
