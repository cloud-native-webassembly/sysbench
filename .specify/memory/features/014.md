# Feature Detail: WASM Layer Automated Tests

**Feature ID**: 014  
**Name**: WASM Layer Automated Tests  
**Description**: Cram/unit coverage for WASM dispatch, backend lifecycle, and data exchange (DFT).  
**Status**: Draft  
**Created**: 2026-08-01  
**Last Updated**: 2026-08-01

## Overview

The WASM layer is roughly 600 lines of C across five files, dispatches through function
pointers, and has zero automated coverage. Every defect recorded in Features 001–011 was
found by reading code, not by a failing test — which is precisely the signal that the
testability gap is the highest-leverage one to close.

This is the DFT (Design for Testability) capability for the WASM layer. It matters more here
than in most subsystems because the failure mode of an untested benchmark is not a crash but
a plausible-looking wrong number.

## Latest Review

Reviewed 2026-08-01 by code inspection during registry bootstrap. Searches for "wasm" in both
`tests/` and `src/tests/` return no matches. `src/tests/` contains only the upstream builtin
tests (`cpu`, `fileio`, `memory`, `threads`, `mutex`). The `cram` framework is already
vendored in `third_party/cram/`, so the harness exists and is simply unused by this layer.

## Key Changes

1. Add cram tests for dispatch (Feature 001): `--type=wasm` with each runtime name, a bogus
   runtime name, and a missing module path — asserting clean error messages rather than
   crashes.
2. Add a smoke test per built backend that runs a small event count against a real workload
   and asserts a nonzero throughput and zero errors.
3. Add a test for the `create_buffer` handshake and packed address encode/decode (Feature
   007), including the negative case of a module without `create_buffer`.
4. Add unit coverage for `sb_wasm_addr_encode` / `sb_wasm_addr_decode` round-tripping,
   including boundary values, since the packing scheme is load-bearing and cheap to test.
5. Add a vtable-completeness test asserting that every registered runtime descriptor has all
   mandatory members non-NULL — this alone would have caught the Wasmer/Wasmtime crash class.
6. Skip rather than fail when an SDK is unavailable, recording an explicit reason, per the
   constitution's `XFAIL` guidance.

## Implementation Notes

- Tests must degrade gracefully by build configuration: a tree configured without
  `--with-wasm` has no WASM binary paths at all, and a tree with only WAMR must not fail
  WasmEdge tests. Gate on the same `HAVE_*` conditionals used by `src/Makefile.am`.
- Backend smoke tests require both the SDK at run time and a compiled workload module, so
  they depend on Feature 008's build producing a stable artefact name — currently the
  `debug.sh` scripts reference names the build never emits (Feature 011).
- Throughput assertions must be qualitative (nonzero, no errors) rather than absolute
  numbers; a test that asserts a latency threshold will be flaky across machines.
- Unit-testing the static functions inside each backend requires either compiling the
  translation unit into a test harness or exercising them through the public vtable; the
  latter is preferable and matches how the code is actually used.
- Coverage tooling already exists in the project (coveralls badge in `README.md`), so the
  WASM layer can be added to the existing report rather than introducing new infrastructure.

## Future Evolution Suggestions

- Add a differential test that runs the same workload on two backends and asserts they
  produce identical computed results, catching marshalling bugs that performance tests miss.
- Add a fuzz or property test over the address packing scheme.
- Once Feature 012 lands, add the leak-check soak run as a periodic rather than per-commit
  job.
