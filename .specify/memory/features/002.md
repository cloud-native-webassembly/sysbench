# Feature Detail: WASM Runtime Abstraction Layer

**Feature ID**: 002  
**Name**: WASM Runtime Abstraction Layer  
**Description**: Defines the shared vtable, sandbox, and module contracts that every WASM engine backend implements.  
**Status**: Implemented  
**Created**: 2026-08-01  
**Last Updated**: 2026-08-01

## Overview

Four WASM engines with four incompatible C APIs cannot each be wired into the sysbench event
loop directly without the loop growing engine-specific branches. This feature is the seam
that prevents that: a single function-pointer table (`sb_wasm_runtime`) plus two data
carriers (`sb_wasm_module`, `sb_wasm_sandbox`) that every backend fills in. The generic layer
in `src/sb_wasm.c` calls only through these pointers, so adding a fifth engine requires no
change to the event loop, and benchmark numbers stay attributable to the engine under test.

This is the load-bearing abstraction for the whole WASM effort and the contract that
Constitution Principle V ("Modular Runtime-Backend Architecture") refers to.

## Latest Review

Reviewed 2026-08-01 by code inspection during registry bootstrap. The vtable and both
carriers are defined and used. Two weaknesses: the interface does not distinguish mandatory
from optional members, so a backend that omits `create_sandbox` compiles and links but
crashes at first use (observed in Features 005 and 006); and `sb_wasm_function` /
`sb_wasm_sandbox_context` are declared as empty structs (`src/sb_wasm.h:41-47`), with each
backend casting `sb_wasm_sandbox_context *` to its own private struct — an unchecked
downcast with no type tag.

## Key Changes

1. Defined the `sb_wasm_runtime` vtable at `src/sb_wasm.h:81-90` with members
   `runtime_type`, `runtime_name`, `init`, `prepare`, `destroy`, `load_module`,
   `create_sandbox`.
2. Defined `sb_wasm_sandbox` at `src/sb_wasm.h:54-64` as the per-thread instance carrying
   `name`, `heap_base`, `buffer_addr`, `context`, `function_apply`, `function_available`,
   `addr_app_to_native`, `addr_native_to_app`.
3. Defined `sb_wasm_module` at `src/sb_wasm.h:66-74` as the per-file descriptor carrying
   `file_buffer`, `file_size`, `stack_size`, `heap_size`, `max_thread_num`, `buffer_size`.
4. Established the opaque-context pattern: `sb_wasm_sandbox_context *` is an empty struct
   that each backend downcasts to its own private context type.
5. Provided a default module loader `sb_wasm_load_module()` (`src/sb_wasm.c:178`) that reads
   the file into a buffer, so a backend may set `load_module = NULL` to opt in
   (`src/sb_wasm.c:203-208`); both working backends do exactly that.
6. Provided the `create_sandbox`-per-thread model: `sb_wasm_op_thread_init`
   (`src/sb_wasm.c:230`) builds one sandbox per sysbench thread into the `sandboxs` array.

## Implementation Notes

- Engine selection is compile-time (`#ifdef HAVE_*`) plus run-time (`switch` on the enum);
  there is no dynamic plugin loading and no shared-object discovery.
- `function_apply` has a deliberately narrow signature
  (`context, fname, thread_id, int64_t *carrier`): exactly one `i64` in, one `i64` out. All
  richer argument passing is squeezed through the packed-address convention of Feature 007.
  This keeps the vtable small but caps what a workload can express.
- `sb_wasm_report_thread_init` and `sb_wasm_report_thread_done` are declared at
  `src/sb_wasm.h:106-108` but never defined in `src/sb_wasm.c` — referencing either would
  fail at link time. See Feature 010.
- The `prepare` member is populated by both working backends but never called by the generic
  layer.
- Status was derived from source inspection during registry bootstrap, not from a completed
  `/speckit.plan` → `/speckit.implement` cycle.

## Future Evolution Suggestions

- Add a `sb_wasm_runtime_validate()` check that asserts mandatory vtable members are
  non-NULL at registration time, converting the Feature 005/006 crash class into a
  startup diagnostic.
- Give `sb_wasm_sandbox_context` a leading `runtime_type` tag so downcasts can be asserted
  in debug builds.
- Widen `function_apply` to accept a typed argument vector so workloads can take multiple
  parameters without the packed-i64 workaround.
- Document the interface contract in `docs/wasm/abstraction.md` (feeds Feature 017),
  including which members are mandatory and who owns each allocation.
