# Feature Detail: WASM Failure Diagnostics

**Feature ID**: 018  
**Name**: WASM Failure Diagnostics  
**Description**: Consistent logger-routed errors and graceful degradation instead of NULL-pointer crashes (DFR).  
**Status**: Draft  
**Created**: 2026-08-01  
**Last Updated**: 2026-08-01

## Overview

The constitution requires that a WASM driver "degrade gracefully when its runtime library is
missing at runtime (clear error message, non-zero exit), never segfault". The current layer
violates that: selecting an unimplemented backend crashes on a NULL function pointer, and
diagnostics are split between the sysbench logger and raw `printf`/`fprintf`, so some
failures bypass verbosity control entirely.

For a benchmark harness the cost is disproportionate. A crash mid-run destroys the result set,
and a diagnostic printed outside the logger does not appear in the captured output that a
developer or agent later reads to understand what went wrong.

## Latest Review

Reviewed 2026-08-01 by code inspection during registry bootstrap. Three concrete defects:
`sb_wasm_op_thread_init` calls `wasm_runtime->create_sandbox` unconditionally
(`src/sb_wasm.c:231`), which is NULL for the Wasmer and Wasmtime descriptors; WasmEdge writes
some failures via `printf` / `fprintf(stderr, ...)` (`src/sb_wasmedge.c:61`, `:101`, `:106`)
rather than `log_text`; and WasmEdge leaves `addr_app_to_native` / `addr_native_to_app`
unassigned on a `malloc`'d sandbox (`src/sb_wasmedge.c:110-115`), so calling either jumps
through indeterminate memory.

## Key Changes

1. Validate runtime descriptors at registration: assert every mandatory vtable member is
   non-NULL in `sb_load_wasm` and fail with "backend <name> is not implemented in this build"
   instead of crashing later.
2. Zero-initialise `sb_wasm_sandbox` (use `calloc` or explicit assignment) so unimplemented
   optional members are reliably NULL, and NULL-check optional members before dispatching
   through them.
3. Route every WASM-layer diagnostic through `log_text` at an appropriate level, removing raw
   `printf` / `fprintf` from `src/sb_wasmedge.c`.
4. Add a capability probe so the generic layer can ask a backend whether it supports address
   translation, replacing the "currently only wamr support it" comment at `src/sb_wasm.c:152`
   with a runtime check.
5. Ensure every failure path returns a non-zero exit status and a message naming the runtime,
   the workload, and the failed operation.
6. Reconcile the header declarations that have no definitions — `sb_wasm_report_thread_init` /
   `sb_wasm_report_thread_done` (`src/sb_wasm.h:106-108`) and the five undefined declarations
   in each of `src/sb_wasmer.h:26-34` and `src/sb_wasmtime.h:26-34` — by implementing or
   deleting them, so the headers stop advertising functions that would fail at link time.

## Implementation Notes

- The NULL-dispatch guard is cheap and should land early: it converts the Feature 005/006
  crash class into a clear message without waiting for those backends to be written, and it is
  what makes selecting an unbuilt runtime safe.
- Guards belong at init and thread-init, not inside the measured per-iteration path, so error
  handling does not perturb the numbers Feature 013 depends on.
- WAMR's error handling is the model to follow: consistent `log_text(LOG_FATAL, ...)` plus
  `goto error` returning `NULL`/`FAILURE`, with SDK exception text surfaced via
  `wasm_runtime_get_exception` (`src/sb_wamr.c:92`).
- Partial-acquisition failure paths currently leak (noted in Feature 012); the unwind logic
  and the diagnostics should be written together since both walk the same acquisition order.
- The dead `error:` label in `sb_wasmedge_init` (`src/sb_wasmedge.c:70`) and the `%p` format
  applied to an `int32_t` at `src/sb_wasm.c:246` are small correctness cleanups belonging to
  this feature.

## Future Evolution Suggestions

- Add a `--wasm-runtime=list` mode printing which backends this binary was built with and
  which are functional, so capability discovery does not require a failed run.
- Distinguish exit codes for configuration errors, missing SDK, module load failure, and
  in-sandbox trap, so scripted sweeps can react appropriately.
- Surface in-sandbox traps with the workload name and iteration index to make intermittent
  failures diagnosable.
